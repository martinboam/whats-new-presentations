## Management

### Slide 4 – Connect your agent estate across platforms

**Connected platforms sync agents from Salesforce, Amazon, Google, Databricks, Snowflake and more into the Agent 365 registry, with no changes to agent code.**

- **Entra Agent ID** — Connected agents get their own identity for lifecycle, access policy and revocation
- **Guided setup** — A step-by-step wizard connects a platform, tools registry or gateway to Agent 365
- **No stored secrets** — Workload identity federation removes long-lived secrets for supported connections

**Status:** Public preview  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/connected-platforms)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)  
**IDs:** none listed

<details><summary>Speaker notes</summary>

Position connected platforms as the way to bring Agentforce, Bedrock, Vertex AI and Databricks agents under the same identity and governance as Microsoft agents. Capabilities vary by platform, so confirm which platforms a customer runs before committing to specific insights or controls.

Entra Agent ID support is rolling out across Salesforce Agentforce, Amazon AgentCore, Google Vertex AI, Databricks, Snowflake, Anthropic Claude Managed Agents, OpenAI, Oracle, SAP, ServiceNow and UiPath, and will complete in December.

</details>

### Slide 5 – Local and shadow agent discovery

**Microsoft Defender and Microsoft Entra Global Secure Access now discover more than 60 local AI agents, such as Claude Code and GitHub Copilot CLI, and add them to the Agent registry.**

- **Device discovery** — Defender ties each local agent to its managed Windows or macOS device and user
- **Network visibility** — Global Secure Access shows each agent's destinations, MCP servers and resources
- **Preview scope** — Network-level discovery and shadow AI in the Agent registry are in preview

**Status:** Generally available  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/agent-shadow-ai)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)  
**IDs:** none listed

<details><summary>Speaker notes</summary>

Shadow AI is the conversation starter: IT and security see agents running outside approved channels in the same inventory as every other agent. Local agent discovery in Microsoft Defender is generally available, while network-level discovery in Global Secure Access and shadow AI discovery in the Agent registry are in preview.

</details>

### Slide 6 – Secure local agents with Entra Agent ID

**Microsoft Entra Agent ID automatically assigns an identity to supported local agents found by Defender and Global Secure Access, starting with GitHub Copilot CLI and Claude Code.**

- **Separate identity** — Each discovered local agent gets its own identity, separate from the user's
- **Agent vs human** — Tell agent activity apart from human activity
- **Access controls** — Apply supported access controls to local agents

**Status:** Public preview  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/entra/agent-id/what-is-microsoft-entra-agent-id)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)  
**IDs:** none listed

<details><summary>Speaker notes</summary>

This closes the gap where a local coding agent acts with the developer's own identity and access. It is in preview and relies on Microsoft Defender on managed devices or Global Secure Access on the network to discover the agents first. Also covered in the Microsoft Ignite 2026 Book of News.

</details>

### Slide 7 – Extend Entra Agent ID to Microsoft Autopilot

**Microsoft Entra Agent ID now extends to Microsoft Autopilot, giving admins a consistent way to identify, authenticate and govern these agents.**

- **Consistent identity** — Builds on existing support for Copilot Studio and Microsoft Foundry agents
- **Secure access** — Admins secure each Autopilot agent's identity and access to resources
- **Tied to its own ID** — Actions Autopilot takes are tied to its own agent ID and safety-checked

**Status:** Public preview  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/entra/agent-id/what-is-microsoft-entra-agent-id)

As Autopilot rolls out through the Frontier program, customers will want each always-on personal agent governed like any other identity. This capability is in preview, so position it with Frontier program customers already piloting Autopilot. Also covered in the Microsoft Ignite 2026 Book of News.

</details>

## Security

### Slide 19 – Dynamic agent risk

**Dynamic agent risk combines runtime signals across identity, access, data, endpoints, cloud and network with exposure and blast radius to deliver one risk level per agent.**

- **Always current** — Updates as an agent acts, becomes a target or receives code or model updates
- **One risk level** — Shown in the Agent 365 registry, Microsoft Defender, Entra and Purview
- **Partner signals** — Check Point, Cyera, Darktrace and Zenity signals via Microsoft Sentinel

**Status:** Public preview  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-agent-365/guidance/detect-risky-agents)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)  
**IDs:** none listed

<details><summary>Speaker notes</summary>

This lets security teams act on the riskiest agents first instead of stitching together signals from siloed tools. It is in preview in Agent 365 and in expanded limited preview within Microsoft Perception. Also covered in the Microsoft Ignite 2026 Book of News.

</details>

### Slide 20 – Identity and access controls that adapt to risk

**Microsoft Entra Conditional Access dynamic controls evaluate policy at the point of action, not only at sign-in, so controls adapt as agent risk and context change.**

- **Point of action** — Policy is evaluated when the agent acts, not only at sign-in
- **Human approval** — Restrict sensitive operations or require approval while low-risk work continues
- **On-behalf-of** — Set policies for agents acting for a user, separate from the user's own

**Status:** Public preview  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/entra/identity/conditional-access/agent-id)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)  
**IDs:** none listed

<details><summary>Speaker notes</summary>

The key message is precision: security teams can restrict a risky agent while preserving the employee's own access. Conditional Access for agents requires Microsoft 365 E7, or Agent 365 with at least Microsoft Entra ID P1 or Microsoft 365 E3.

</details>

- **Key local agents** — Claude Code, Claude Desktop, GitHub Copilot CLI and the GitHub Copilot app
- **Flexible scoping** — Apply policies to individual agents, groups of agents or the whole organization
- **Follows the agent** — Data protection follows agents in the cloud and on supported devices

**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/purview/ai-agent-365)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)

</details>

## Business Value

### Slide 25 – Agent 365 Business Analytics

**Agent 365 Business Analytics helps business leaders see where AI investments deliver value, bringing Microsoft and non-Microsoft AI spend, usage and value together in one place.**

- **Understand spend** — See what drives AI costs in dollars and where spend is concentrated
- **Measure value** — Assisted hours, assisted value, success rate and satisfaction by use case
- **Plan investment** — Spend forecasts, scenario planning and sharing through Outlook or Teams

**Status:** Rolling out  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/a365-business-analytics/introduction)  
**Source:** [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)  
**IDs:** Roadmap [577548](https://www.microsoft.com/en-us/microsoft-365/roadmap?id=577548)

<details><summary>Speaker notes</summary>

Satya Nadella described Business Analytics as an ERP system for AI usage, giving business leaders a clear line between AI spend and the value it creates. Analytics for Microsoft services need at least one Microsoft 365 Copilot license in the tenant, while connected non-Microsoft AI services need Agent 365 or Microsoft 365 E7 licensing. Also covered in Ignite 2026: Building the frontier ecosystem and the Microsoft Ignite 2026 Book of News.

Agent 365 Business Analytics began rolling out in the Frontier program on November 17, 2026.

Access and prerequisites: Access follows the org chart and existing Viva Insights roles, so leaders see insights for their own organization without new role assignments. The top three layers of the organization (the CEO, their direct reports and the next level) get tenant-level access, managers of teams of 10 or more see insights for their own organization, and Microsoft 365 global admins have access by default. Viva Insights minimum group size settings carry over and hide insights for smaller groups. Cost, budget and usage-based insights appear only when consumption insights are on for a role: on by default for general managers, but an admin must turn them on for business leaders.

Before you start: Microsoft Learn lists at least 50 Copilot licenses assigned, spending policies set up for usage-based services, and billing turned on in the Microsoft 365 admin center. The Ignite blogs say at least one Microsoft 365 Copilot license, so check the Learn page before quoting a number. Learn page: Introduction to Agent 365 Business Analytics (Frontier) — https://learn.microsoft.com/en-us/a365-business-analytics/introduction

</details>

### Slide 27 – Business Analytics: Understand the value AI is creating

**Business Analytics maps AI activity to more than 6,000 business use cases and estimates the value of the work AI helps people complete.**

- **Use case taxonomy** — Drill from domain to category, subcategory and use case with cost and assisted hours
- **Value signals** — Dollar value, assisted hours, success rate and satisfaction across Microsoft and other AI
- **Tailored assumptions** — Value model based on O*NET, US labor data and LinkedIn, adjustable to your business

**Status:** Rolling out  
**Learn more:** [Microsoft Learn](https://learn.microsoft.com/en-us/a365-business-analytics/use-cases)  
**Source:** [Introducing Microsoft Agent 365 Business Analytics](https://techcommunity.microsoft.com/blog/ai-finops-blog/introducing-microsoft-agent-365-business-analytics-turn-ai-investment-into-busin/4574149)  
**IDs:** none listed

<details><summary>Speaker notes</summary>

Assisted hours combine the typical time a completed task takes with AI's estimated contribution, so position them as a directional estimate of work AI helped complete, not measured time saved or financial return. Classification uses Microsoft's predefined taxonomy rather than customer content, so confidential project names never become reporting categories.

Use case mapping is rolling out in the Frontier program from November 2026; value against investment arrives for Copilot Cowork in November 2026 and for agents in December 2026.

</details>
